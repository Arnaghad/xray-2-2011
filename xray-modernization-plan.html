01 · P0 Зафіксувати відтворювану Windows-збірку

У поточному дереві є CMake-пресети Windows x64 Debug і Release, обов’язкові CPU-тести й workflow модернізації. Їхні результати створять базу для порівняння до й після переходу на SDL3.

  • Фіксувати версії, список DLL-імпортів, попередження та виміри для повторюваних сцен. Додати перевірку пакування SDL3 та smoke-тест запуску Windows після міграції.

03 · P0 Прибрати ризики в активному C++

GCC 16.2 у Release видає -Wstrict-aliasing для бінарних конфігів, math::abs/floor/ceil і WildMagic4. Кореневий CMake глобально вимикає частину діагностик, зокрема форматування та копіювання об’єктів.

  • Замість читання через приведені вказівники запровадити явно визначене декодування бітів і байтів. Зафіксувати знаковість, розміри, порядок байтів і поведінку для граничних чисел. Окремо перевірити діапазони й зсуви в floor/ceil та попередження кукера шкіри.
  • Почати із вузьких ділянок VFS та configs. Використати std::span для буферів із межами та RAII для Win32/COM-ресурсів. Поступово повертати попередження за модулями, перевіряти санітайзерами там, де це підтримує вибраний toolchain.
  • Після появи тестів життєвого циклу замінювати локальні boost::bind на лямбди й FastDelegate по одному клієнту. Для callback окремо перевірити володіння, відписку та порядок викликів. Зміни allocator/TLS/APC і потоків робити окремими PR.

Критерій приймання. Debug і Release однаково читають еталонні архіви та конфіги. Перевірено крайні значення, закриття ресурсів і порядок callback. Для часто викликаної математики порівняно продуктивність.

04 · P1 Перейти на SDL3 у Windows-збірці

CMake підключає SDL2, а активний ввід створює DirectInput 8. Наявний Windows Release напряму імпортує XINPUT1_3.dll. Ціль етапу — спільний SDL3-шлях для вікна гри й вводу, який можна зібрати під Windows та Linux.

  • Замінити SDL2 на find_package(SDL3 CONFIG REQUIRED) та SDL3::SDL3. Закріпити версію пакета в MSYS2/CI, перевірити точку входу й включити потрібний SDL3 runtime у Windows-пакет. Підключати SDL3 до цілей, які його використовують.
  • Перевести клавіатуру, відносний рух миші та геймпади на SDL3 за наявним xray::input API. Зберегти прив’язки дій, порядок подій і відновлення стану після втрати фокуса. Обробляти чергу SDL у головному потоці, передавати нормалізовані події до логіки рушія. Після підтвердження паритету вилучити прямі залежності рушія від DirectInput і XInput.
  • Ігрове вікно створювати з SDL_WINDOW_VULKAN. Отримувати Vulkan instance extensions і створювати surface через SDL_Vulkan_GetInstanceExtensions та SDL_Vulkan_CreateSurface. Передавати створення й життєвий цикл surface через платформний інтерфейс, який також підтримує headless. Інтеграцію вбудованого HWND редактора тримати в адаптері Win32 та перевіряти окремо.
  • Окремими PR перевірити XAudio2 2.9 у Windows-аудіобекенді, консолідувати локальні дампи через DbgHelp і винести тестовий UDP-обмін в окрему ціль. У Linux-порті підключити аудіобекенд за спільним інтерфейсом звуку та оцінити SDL3 Audio з перевіркою потокового відтворення.

Критерій приймання. Windows Debug/Release збираються з SDL3, а пакет запускається на чистій Windows. Перевірено клавіатуру, фокус і Alt+Tab, відносний рух миші, гаряче підключення і вібрацію геймпадів. Vulkan Validation проходить запуск, resize, minimize та закриття гри й вбудованого в’юпорта. SDL2, DirectInput і XInput відсутні серед прямих залежностей ігрового runtime.

09 · P2 Зібрати й перевірити Linux x64

Першими підключити кукер і переносимі CPU-тести, далі ядро та ігровий runtime. Для Linux перевіряти доступність SDL3, Vulkan, DXC або підготовлених шейдерів, пакування залежностей, чутливість до регістру шляхів і читання старих асетів.
